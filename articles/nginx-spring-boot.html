NGINX + Spring Boot؛ استقرار حرفه‌ای در Production

Spring Boot سرور Tomcat تعبیه‌شده دارد، اما در Production معمولاً NGINX را جلوی آن می‌گذاریم تا TLS، فایل استاتیک، Gzip و Timeout را مدیریت کند. نکته‌ی کلیدی، انتقال درست هدرهای X-Forwarded-* است.

بخش ۱مقدمه

Spring Boot با Tomcat داخلی به‌تنهایی می‌تواند سرویس بدهد، اما گذاشتن آن مستقیم روی اینترنت اشتباه است: مدیریت گواهی TLS، محدودسازی نرخ، فایل استاتیک و Timeoutها همه به عهده‌ی برنامه می‌افتد. راه‌حل استاندارد، قرار دادن NGINX به‌عنوان Reverse Proxy در لبه است.

در این مقاله پیکربندی upstream و TLS، انتقال هدرهای Forwarded، تنظیمات application.yml و عیب‌یابی رایج.
Prerequisites Reverse Proxy و NGINX.

بخش ۲چرا NGINX جلوی Spring Boot؟

وظیفهکدام لایه
TLS TerminationNGINX
سرو فایل استاتیک و کشNGINX
Rate Limit و WAFNGINX
منطق کسب‌وکار و APISpring Boot
Access Log سطح لبهNGINX
اصل تفکیک مسئولیت NGINX مسائل «لبه» را حل می‌کند و Spring Boot روی «منطق» تمرکز می‌کند. این تفکیک، هم امن‌تر است و هم توسعه و استقرار را ساده‌تر می‌کند.

بخش ۳معماری و جریان درخواست

بخش ۴پیکربندی NGINX و Spring

upstream spring_app {
    server 127.0.0.1:8080;
    keepalive 32;
}

server {
    listen 443 ssl http2;
    server_name api.example.com;
    ssl_certificate     /etc/letsencrypt/live/api.example.com/fullchain.pem;
    ssl_certificate_key /etc/letsencrypt/live/api.example.com/privkey.pem;

    client_max_body_size 20m;      # آپلود فایل

    location / {
        proxy_pass http://spring_app;
        proxy_http_version 1.1;
        proxy_set_header Host              $host;
        proxy_set_header X-Real-IP         $remote_addr;
        proxy_set_header X-Forwarded-For   $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
        proxy_set_header Connection        "";
        proxy_read_timeout 60s;
    }

    location /static/ {
        alias /var/www/app/static/;
        expires 30d;
        add_header Cache-Control "public, immutable";
    }
}
# application.yml
server:
  port: 8080
  forward-headers-strategy: framework   # احترام به X-Forwarded-*
  tomcat:
    threads:
      max: 200
    max-connections: 10000
  compression:
    enabled: true

management:
  endpoints:
    web:
      exposure:
        include: health,metrics,prometheus
Expected Behavior NGINX TLS را تمام می‌کند و هدرهای Forwarded را می‌فرستد؛ Spring Boot با forward-headers-strategy: framework آن‌ها را می‌خواند تا Redirectها و لاگ‌ها با https و IP واقعی کاربر درست باشند.
دام رایج بدون تنظیم forward-headers-strategy، برنامه فکر می‌کند درخواست روی HTTP آمده و Loop ریدایرکت یا URLهای اشتباه تولید می‌کند.

بخش ۵Production و عیب‌یابی

# اجرای Spring Boot با systemd
# /etc/systemd/system/myapp.service
# [Service]
# User=app
# ExecStart=/usr/bin/java -Xms512m -Xmx1024m -jar /opt/app/app.jar
# Restart=always

sudo systemctl daemon-reload
sudo systemctl enable --now myapp
sudo systemctl status myapp
نشانهعلت احتمالیراه‌حل
502 Bad GatewaySpring Boot down یا پورت اشتباهبررسی systemd و proxy_pass
504 Gateway Timeoutپاسخ کند برنامهافزایش proxy_read_timeout یا بهینه‌سازی کوئری
Redirect به httpهدر Forwarded تنظیم نشدهforward-headers-strategy
413 Request Entity Too Largeمحدودیت آپلودclient_max_body_size
IP کاربر در لاگ نامعتبرعدم خواندن X-Forwarded-Forهدر و strategy
Production Note همیشه یک Endpoint سلامت (/actuator/health) داشته باشید و آن را در Load Balancer و systemd برای Restart خودکار به کار ببرید.
