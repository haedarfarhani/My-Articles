Microsoft IIS؛ Web Server ویندوز و میزبانی ASP.NET Core

IIS (Internet Information Services) Web Server بومی ویندوز است و ستون فقرات میزبانی ASP.NET و ASP.NET Core در محیط‌های Microsoft به‌شمار می‌رود. در این مقاله Application Pool، ماژول ASP.NET Core، پیکربندی web.config و استفاده از ARR به‌عنوان Reverse Proxy را بررسی می‌کنیم.

بخش ۱مقدمه

در دنیای ویندوز و سرویس‌های Microsoft، IIS جایگاه NGINX در دنیای لینوکس را دارد: هم فایل استاتیک سرو می‌کند، هم میزبان برنامه‌های .NET است و هم می‌تواند نقش Reverse Proxy را بازی کند. اگر با ASP.NET Core کار می‌کنید، شناخت IIS برای استقرار حرفه‌ای ضروری است.

در این مقاله Application Pool، ماژول ASP.NET Core، فایل web.config، URL Rewrite و ARR به‌عنوان Reverse Proxy.
Prerequisites Web Server و Web Server vs Application Server.

بخش ۲IIS چیست؟

تعریف Microsoft IIS یک Web Server و Platform میزبانی است که به‌صورت یکپارچه در Windows Server وجود دارد و با موتور HTTP.sys درخواست‌ها را دریافت و بین Application Poolها توزیع می‌کند.
مفهومتوضیح
HTTP.sysدرایور Kernel-mode که سوکت و TLS را مدیریت می‌کند
Application Poolمرز جداسازی و اجرای یک یا چند برنامه در w3wp.exe
Site / Bindingاتصال دامنه و پورت به یک برنامه
web.configفایل پیکربندی سطح برنامه (Rewrites، Headers، Limits)

بخش ۳معماری و Application Pool

Recycling هر Application Pool را می‌توان زمان‌بندی کرد تا در بازه‌های مشخص بازیافت شود؛ اما این کار اتصال‌های جاری را می‌بندد. برای Zero-Downtime از Overlapped Recycle استفاده کنید.

بخش ۴میزبانی ASP.NET Core

ASP.NET Core یک سرور سبک به‌نام Kestrel دارد. در IIS، ماژول AspNetCoreModuleV2 به‌عنوان Reverse Proxy درون‌فرآیندی یا برون‌فرآیندی عمل می‌کند و درخواست‌ها را به Kestrel می‌سپارد. 

<!-- web.config -->
<configuration>
  <system.webServer>
    <handlers>
      <add name="aspNetCore" path="*" verb="*"
           modules="AspNetCoreModuleV2" resourceType="Unspecified" />
    </handlers>
    <aspNetCore processPath="dotnet"
                arguments=".\MyApp.dll"
                hostingModel="inprocess">
      <environmentVariables>
        <environmentVariable name="ASPNETCORE_ENVIRONMENT" value="Production" />
      </environmentVariables>
    </aspNetCore>
  </system.webServer>
</configuration>
// Program.cs — احترام به هدرهای پروکسی
var builder = WebApplication.CreateBuilder(args);
builder.Services.Configure<ForwardedHeadersOptions>(o => {
    o.ForwardedHeaders = ForwardedHeaders.XForwardedFor |
                         ForwardedHeaders.XForwardedProto;
});

var app = builder.Build();
app.UseForwardedHeaders();
app.MapGet("/health", () => Results.Ok(new { status = "ok" }));
app.Run();
Expected Behavior در حالت inprocess، برنامه داخل همان فرآیند w3wp.exe اجرا می‌شود و کارایی بالاتری دارد؛ در outofprocess، Kestrel به‌عنوان فرآیند جدا روی یک پورت محلی گوش می‌دهد.

بخش ۵Reverse Proxy با ARR و HTTPS

افزونه‌ی ARR (Application Request Routing) به IIS امکان Reverse Proxy و Load Balancing می‌دهد؛ مکمل آن URL Rewrite است که قواعد مسیر را تعریف می‌کند. 

<!-- Reverse Proxy به Backend داخلی -->
<rule name="ProxyToApi" stopProcessing="true">
  <match url="^api/(.*)" />
  <action type="Rewrite" url="http://10.0.0.11:8080/{R:1}" />
</rule>
موضوعتصمیم Production
TLSگواهی روی Binding پورت ۴۴۳، HSTS فعال
Security Headersاز طریق web.config یا Middleware
Request LimitsmaxAllowedContentLength متناسب با Upload
Identityاجرای App Pool با حساب کم‌دسترسی
LoggingW3C Logs و ارسال به مرکز لاگ
Production Note خاموش‌کردن Detailed Errors در محیط Production الزامی است؛ پیام‌های خطای کامل می‌توانند مسیرها و ساختار داخلی برنامه را افشا کنند.
