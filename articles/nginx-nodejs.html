NGINX + Node.js؛ Reverse Proxy، PM2 و WebSocket

Node.js برای بارهای همزمان عالی است، اما سرو فایل استاتیک، TLS و مدیریت چند Process کار آن نیست. NGINX این وظایف را به‌خوبی انجام می‌دهد. در این مقاله ترکیب NGINX با PM2، keepalive و WebSocket را می‌سازیم.

بخش ۱مقدمه

Node.js یک Application Server سبک است، اما در Production گذاشتن آن مستقیم روی پورت 80 اشتباه است: TLS، فایل استاتیک، محدودیت نرخ و Timeout همه به دوش برنامه می‌افتد. الگوی درست، ترکیب NGINX در لبه با PM2 برای مدیریت چند Worker است.

در این مقاله پیکربندی upstream با Keep-Alive، فعال‌سازی PM2 Cluster، پشتیبانی WebSocket و سرو فایل استاتیک.
Prerequisites Node.js HTTP Server و NGINX.

بخش ۲معماری PM2 + NGINX

بخش ۳upstream و Keep-Alive

upstream node_app {
    least_conn;
    server 127.0.0.1:3001;
    server 127.0.0.1:3002;
    server 127.0.0.1:3003;
    server 127.0.0.1:3004;

    keepalive 64;                     # اتصال‌های پایدار به Backend
}

server {
    listen 443 ssl http2;
    server_name app.example.com;
    ssl_certificate     /etc/letsencrypt/live/app.example.com/fullchain.pem;
    ssl_certificate_key /etc/letsencrypt/live/app.example.com/privkey.pem;

    location / {
        proxy_pass         http://node_app;
        proxy_http_version 1.1;                       # لازم برای keepalive
        proxy_set_header   Connection "";             # پاک‌کردن Connection
        proxy_set_header   Host              $host;
        proxy_set_header   X-Real-IP         $remote_addr;
        proxy_set_header   X-Forwarded-For   $proxy_add_x_forwarded_for;
        proxy_set_header   X-Forwarded-Proto $scheme;
    }
}
Expected Behavior NGINX به‌جای بازکردن اتصال جدید برای هر درخواست، از Connection Pool پایدار به Workerها استفاده می‌کند؛ این کار تأخیر و مصرف سوکت را به‌شدت کاهش می‌دهد.
کلید کار در سمت Node.js مقدار server.keepAliveTimeout را کمی بیشتر از keepalive_timeout در NGINX بگذارید تا Race Condition اتصال رخ ندهد.

بخش ۴WebSocket و Proxy Upgrade

# مسیر WebSocket
location /ws/ {
    proxy_pass         http://node_app;
    proxy_http_version 1.1;
    proxy_set_header   Upgrade    $http_upgrade;
    proxy_set_header   Connection "upgrade";
    proxy_set_header   Host       $host;
    proxy_read_timeout 3600s;      # اتصال طولانی
    proxy_send_timeout 3600s;
}
معمای رایج اگر Upgrade و Connection را نفرستید، Handshake ناموفق می‌شود و Client هر چند ثانیه Reconnect می‌کند؛ در ظاهر سایت کار می‌کند اما Realtime از کار افتاده است.
Sticky برای Socket اگر سرویس Real-time شما State روی Process نگه می‌دارد، از ip_hash در upstream استفاده کنید یا State را در Redis مشترک بگذارید.

بخش ۵فایل استاتیک و Compression

# سرو فایل استاتیک بیلدشده (Next/Nuxt/React build)
location /build/ {
    alias /var/www/app/build/;
    expires 1y;
    add_header Cache-Control "public, immutable";
}

location / {
    proxy_pass http://node_app;
}

# Gzip
gzip on;
gzip_comp_level 5;
gzip_min_length 256;
gzip_types text/css application/javascript application/json image/svg+xml;
چرا مهم است؟ سرو فایل استاتیک توسط NGINX به‌جای Node، هم CPU برنامه را آزاد می‌کند و هم با Cache-Control بار تکرارشونده را حذف می‌کند.

بخش ۶Production و عیب‌یابی

# ساختار PM2
pm2 start ecosystem.config.js --env production
pm2 save
pm2 startup      # سرویس systemd برای اجرا پس از ری‌استارت
pm2 reload all   # Reload بدون قطعی (Zero-Downtime)
pm2 logs api --lines 100
نشانهعلت احتمالیراه‌حل
502 Bad Gatewayهیچ Worker بالای پورت نیستبررسی pm2 status
504 Gateway Timeoutعملیات کند یا Event Loop قفلافزایش Timeout یا تفکیک کار CPU-bound
WebSocket قطع می‌شودهدرهای Upgrade تنظیم نشدهتنظیم Connection: upgrade
Session گم می‌شودچند Worker و State محلیSession در Redis
Restart زیادمصرف حافظه یا خطای برنامهبررسی pm2 logs و سقف حافظه
Production Note هرگز --watch را در Production فعال نکنید؛ با هر تغییر فایل، سرویس Restart و اتصال‌ها قطع می‌شود.

بخش ۷جمع‌بندی

مزایامعایب
کارایی بالای Keep-Alive و استاتیکنگهداری دو لایه (NGINX + PM2)
Zero-Downtime Reload با PM2مدیریت Session در چند Worker حساس است
پشتیبانی خوب Realtimeنیاز به تنظیم دقیق Timeoutها
When to Useهر API یا اپلیکیشن Node.js که در Production بار واقعی دارد و به TLS، فایل استاتیک و Realtime نیاز دارد.

ترکیب NGINX و PM2 الگوی استاندارد و اثبات‌شده‌ی اجرای Node.js است. با Keep-Alive، هدرهای درست و Session مشترک، سرویسی سریع و پایدار خواهید داشت.
