Apache Tomcat؛ Servlet Container و Application Server برای Java

Tomcat را نباید صرفاً یک Web Server عمومی دانست؛ آن یک Servlet Container و Application Server سبک است که برنامه‌ی Java را درون JVM اجرا می‌کند. در این مقاله معماری Catalina و Coyote و Jasper، Connector و Thread Pool، استقرار WAR، JNDI و DataSource را می‌بینیم.

بخش ۱مقدمه

Tomcat برای اجرای برنامه‌های Java وب ساخته شده است. برخلاف NGINX که یک Web Server عمومی است، Tomcat یک میزبان برنامه است: چرخه‌ی حیات Servlet، مدیریت Session، تراکنش و اتصال دیتابیس را در اختیار برنامه می‌گذارد.

در این مقاله یاد می‌گیرید اجزای داخلی Tomcat، پیکربندی Connector و Thread Pool، استقرار WAR و تنظیمات Production برای JVM و امنیت.
Prerequisites Web Server vs Application Server.

بخش ۲Tomcat چیست؟

تعریف Apache Tomcat یک Servlet Container و پیاده‌سازی مرجع Jakarta Servlet است که برنامه‌ی Java را درون JVM اجرا می‌کند و درخواست‌های HTTP را به Servletها می‌رساند. نسخه‌های جدید Tomcat 10+ روی jakarta.* کار می‌کنند (نه javax.*).
مفهوممعنا
Servletکلاسی که درخواست HTTP را پردازش می‌کند
WARبسته‌ی برنامه‌ی وب برای استقرار
JSPقالب صفحه که به Servlet کامپایل می‌شود
Contextیک برنامه‌ی مستقر (مسیر URL آن)

بخش ۳معماری: Catalina، Coyote، Jasper

بخش ۴Connector و Thread Pool

<!-- conf/server.xml -->
<Connector port="8080"
           protocol="HTTP/1.1"
           connectionTimeout="20000"
           redirectPort="8443"
           maxThreads="200"
           acceptCount="100"
           minSpareThreads="25"
           maxConnections="10000" />
پارامترمعنااثر Production
maxThreadsحداکثر Thread پردازش همزمانکوچک = صف طولانی؛ بزرگ = مصرف CPU و Context Switching
acceptCountاندازه‌ی صف انتظار اتصالاشباع این صف = خطای اتصال
maxConnectionsحداکثر اتصال همزمانمرتبط با Keep-Alive و تعداد کلاینت
connectionTimeoutزمان انتظار برای درخواستمحافظت از Threadهای بی‌کار
redirectPortپورت ریدایرکت HTTPSبرای transport-guarantee
Production Note maxThreads را با ظرفیت Connection Pool دیتابیس هماهنگ کنید. اگر ۲۰۰ Thread داشته باشید اما Pool فقط ۲۰ اتصال، درخواست‌ها در صف Connection می‌مانند و Latency افزایش می‌یابد.

بخش ۵Deployment و مسیرها

my-app.war
      ↓  کپی به
$CATALINA_HOME/webapps/
      ↓  Tomcat خودکار باز می‌کند
$CATALINA_HOME/webapps/my-app/
      ↓  Context در دسترس
http://host:8080/my-app/
روش استقرارتوضیح
Manualکپی WAR در webapps/ و Restart
Manager Appاستقرار از رابط وب (فقط پشت Auth)
Maven Plugintomcat7-maven-plugin / cargo-maven3-plugin
CI/CDساخت WAR در Pipeline و انتشار روی سرور
Dockerتصویر رسمی tomcat:10-jdk21 و Mount پیکربندی
systemdسرویس مستقیم روی JVM با catalina.sh run
# استقرار سطح Production با systemd
export JAVA_OPTS="-Xms512m -Xmx1024m -XX:+UseG1GC"
$CATALINA_HOME/bin/catalina.sh run

# Docker
docker run -d --name tomcat -p 127.0.0.1:8080:8080 \
  -v /opt/app/my-app.war:/usr/local/tomcat/webapps/my-app.war \
  tomcat:10-jdk21
Common Mistake قرار دادن Secret (رمز دیتابیس، کلید API) در context.xml داخل WAR. این فایل در تصویر و مخزن می‌ماند. مقادیر حساس را از Environment Variable یا JNDI سطح سرور بدهید.

بخش ۶Session، JNDI و DataSource

<!-- conf/context.xml -->
<Context>
  <Resource name="jdbc/appdb"
            auth="Container"
            type="javax.sql.DataSource"
            maxTotal="50"
            maxIdle="10"
            maxWaitMillis="10000"
            username="${DB_USER}"
            password="${DB_PASSWORD}"
            driverClassName="org.postgresql.Driver"
            url="jdbc:postgresql://db.internal:5432/app" />
</Context>
موضوعنکته‌ی Production
Session در حافظهمانع Scaling افقی می‌شود؛ Sticky Session لازم است
Session با Redisرویکرد Stateless و قابل مقیاس
DataSource از JNDIمدیریت متمرکز Connection Pool
Connection Leakهمیشه از try-with-resources استفاده کنید
Session Replication Clustering با DeltaManager یا BackupManager می‌تواند گران باشد. برای اکثر معماری‌ها، انتقال Session به Redis ساده‌تر و مقیاس‌پذیرتر است.

بخش ۸مزایا، معایب و جمع‌بندی

AdvantagesDisadvantages
پیاده‌سازی مرجع Servlet و سازگاری بالااجرای منطق برنامه درون همان فرآیند، بدون جداسازی لبه
سبک نسبت به Application Server کاملReverse Proxy و TLS پیشرفته ندارد
اکوسیستم بالغ Java و مستندات فراوانپیکربندی XML و مدیریت Connector نیاز به دانش دارد
When to Useاستقرار WAR روی JVM، اپلیکیشن‌های Jakarta Servlet و Spin up سریع سرویس Java.
When NOT to Useبرای لبه و سرو فایل ثابت و TLS عمومی، NGINX/Caddy مناسب‌تر است. برای Jakarta EE کامل، TomEE یا WildFly.

Tomcat یک Application Server سبک و استاندارد است. بهترین معماری Production: NGINX در لبه و Tomcat در شبکه‌ی خصوصی.
