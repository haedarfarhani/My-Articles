بخش ۱IP چیست و چرا مهم است؟

آدرس IP (Internet Protocol Address) شناسه‌ی منطقی هر دستگاه در یک شبکه‌ی IP است. نقش آن دقیقاً مثل نشانی پست است: بسته‌ی داده (Packet) باید بداند به کدام دستگاه برود و پاسخ را به کدام دستگاه برگرداند. آدرس IP برخلاف MAC Address فیزیکی نیست و با جابه‌جا شدن دستگاه یا شبکه، تغییر می‌کند.

بخش ۲آناتومی IPv4: بیت، اکتت، Network و Host

آدرس IPv4 از چهار عدد بین ۰ تا ۲۵۵ ساخته شده که با نقطه جدا می‌شوند و هر عدد یک اکتت (Octet) یا ۸ بیت است. پس کل آدرس ۳۲ بیت است. این ۳۲ بیت همیشه به دو بخش تقسیم می‌شود: بخش Network (کدام شبکه؟) و بخش Host (کدام دستگاه در آن شبکه؟). مرز این دو بخش را Subnet Mask تعیین می‌کند. 

آدرس:    192      . 168      . 10       . 50
باینری:  11000000 . 10101000 . 00001010 . 00110010
وزن بیت: 128+64   . 128+32+8 . 8+2      . 32+16+2
         = 192      = 168      = 10       = 50

# دو آدرس در هر شبکه رزرو است:
#   Network Address   → همه‌ی بیت‌های Host صفر   (192.168.10.0)
#   Broadcast Address → همه‌ی بیت‌های Host یک    (192.168.10.255)
# پس تعداد میزبان قابل استفاده = 2^h - 2
نمایش دودویی چرا؟ همه‌ی محاسبات Subnetting در واقع عملیات بیتی است: AND برای پیدا کردن Network و OR برای Broadcast. اگر بتوانید آدرس را ذهنی به باینری ببرید، دیگر نیازی به حفظ کردن جدول‌ها ندارید.

بخش ۵محاسبات شبکه: Network، Broadcast و بازه‌ی Host

همه‌ی محاسبات از یک ایده‌ی ساده می‌آید: Network Address = IP AND Mask و Broadcast = Network + BlockSize − 1. برای شبکه‌های /25 تا /32 کار ساده‌تر هم می‌شود، چون Block Size فقط به اکتت آخر ربط دارد.

فرمول‌های اساسی Block Size = ۲h (h = تعداد بیت میزبان) · Network = IP AND Mask · Broadcast = Network OR Wildcard = Network + BlockSize − 1 · Host Range = Network+1 تا Broadcast−1 · تعداد زیرشبکه = ۲b (b = بیت قرض‌گرفته‌شده) 
مثال گام‌به‌گام — 172.16.20.130/27

گام ۱) ماسک /27 = 255.255.255.224  →  ۲۷ بیت شبکه، ۵ بیت میزبان
گام ۲) Block Size = 2^5 = 32
گام ۳) 130 ÷ 32 = 4.06  →  چهار بلوکِ کامل  →  4 × 32 = 128
       پس Network = 172.16.20.128
گام ۴) Broadcast = 128 + 32 − 1 = 159   →  172.16.20.159
گام ۵) Host Range = 172.16.20.129 .. 172.16.20.158  (۳۰ میزبان)
گام ۶) اکتت چهارم تغییر می‌کند: .128 و .160 و .192 و .224 بلوک‌های مجاوراند

باینری (اکتت چهارم):
  130 = 10000010
  224 = 11100000   (ماسک)
  AND = 10000000 = 128   ✔ Network
  OR  = 10011111 = 159   ✔ Broadcast

بخش ۶Subnetting: تقسیم یک شبکه به زیرشبکه

Subnetting یعنی قرض‌گرفتن بیت از بخش میزبان و ساختن چند شبکه‌ی کوچک‌تر. دلیلش فقط «کمبود آدرس» نیست: جداسازی ترافیک، کاهش Broadcast Domain، اعمال سیاست‌های امنیتی و مستندسازی تمیزتر از دلایل اصلی‌اند. 

# تقسیم خودکار یک شبکه بر اساس تعداد میزبان مورد نیاز
ipcalc -s 62 62 62 62 192.168.1.0/24        # چهار زیرشبکه‌ی /26
ipcalc -s 30 30 30 30 30 30 10.0.0.0/24     # شش زیرشبکه‌ی /27
ipcalc -s 500 10.0.0.0/22                   # بر اساس میزبان، پیشوند را انتخاب می‌کند

# تقسیم دستی به بلوک‌های /28
subnetcalc 192.168.1.0/24 -s 28

اشتباه رایج کوچک‌کردن بیش‌ازحد subnet باعث هدررفت آدرس و پیچیدگی مسیریابی می‌شود؛ بزرگ‌کردنش Broadcast Domain را بزرگ و جداسازی امنیتی را بی‌اثر می‌کند. مرز را بر اساس «تعداد دستگاه + رشد ۲۰٪» انتخاب کنید، نه بر اساس مد روز.

بخش ۷VLSM: تخصیص بهینه‌ی فضای آدرس

در Subnetting ساده همه‌ی زیرشبکه‌ها یک اندازه دارند. اما نیازها یکسان نیستند: یک لینک Point-to-Point حداکثر ۲ آدرس می‌خواهد و یک طبقه‌ی اداری ۱۰۰ آدرس. VLSM (Variable Length Subnet Masking) اجازه می‌دهد هر زیرشبکه ماسک متفاوتی داشته باشد. قانون طلایی: از بزرگ‌ترین نیاز به کوچک‌ترین تخصیص بدهید. 

# ترتیب نیازها دقیقاً مثل ترتیب تخصیص ماست: بزرگ به کوچک
ipcalc -s 100 50 25 5 2 10.0.0.0/24

# بررسی اینکه بلوک‌ها روی هم نیفتاده‌اند (بدون هم‌پوشانی)
for cidr in 10.0.0.0/25 10.0.0.128/26 10.0.0.192/27 10.0.0.224/30 10.0.0.232/29; do
  ipcalc -n "$cidr"
done

#!/bin/bash
# vlsm_plan.sh — طرح VLSM خودکار برای یک شبکه‌ی پایه
# استفاده: ./vlsm_plan.sh 10.0.0.0/24 100 50 25 5 2

set -euo pipefail
BASE=$1; shift
NEEDS=("$@")

python3 - "$BASE" "${NEEDS[@]}" <<'PY'
import ipaddress, sys
base = ipaddress.ip_network(sys.argv[1], strict=False)
needs = sorted((int(n) for n in sys.argv[2:]), reverse=True)   # بزرگ به کوچک
cursor = int(base.network_address)
for need in needs:
    h = max(2, need + 2)                       # +2 برای Network و Broadcast
    prefix = 32 - (h - 1).bit_length()         # کوچک‌ترین بلوک کافی
    net = ipaddress.ip_network((cursor, prefix))
    print(f"need={need:4d}  {str(net):20} hosts={net.num_addresses - 2:4d}  {net.netmask}")
    cursor = int(net.broadcast_address) + 1
free = base.num_addresses - (cursor - int(base.network_address))
print(f"remaining addresses for growth: {free}")
PY

بخش ۸Supernetting و Route Summarization

Supernetting (یا Route Summarization / Aggregation) عکس Subnetting است: چند شبکه‌ی پیوسته را در یک اعلان مسیر خلاصه می‌کنیم. نتیجه، جدول مسیریابی کوچک‌تر، همگرایی سریع‌تر و نوسان کمتر (flapping) است. شرط اصلی، پیوستگی و هم‌ترازی بلوک‌هاست. 

# پیدا کردن خلاصه‌ی یک مجموعه‌ی شبکه‌ی پیوسته با colliwobbles-free روش استاندارد
python3 - <<'PY'
import ipaddress
nets = [ipaddress.ip_network(n) for n in
        ("192.168.0.0/24", "192.168.1.0/24", "192.168.2.0/24", "192.168.3.0/24")]
summary = list(ipaddress.collapse_addresses(nets))
print("summary:", [str(s) for s in summary])      # ['192.168.0.0/22']

# اگر شبکه‌ها پیوسته نباشند، چند مسیر باقی می‌ماند
mixed = [ipaddress.ip_network(n) for n in ("192.168.0.0/24", "192.168.2.0/24")]
print("mixed:  ", [str(s) for s in ipaddress.collapse_addresses(mixed)])
PY

بخش ۹IPv6: آدرس‌دهی نسل جدید

IPv6 با ۱۲۸ بیت، فضای آدرس را عملاً بی‌پایان می‌کند و در کنار آن Broadcast را حذف کرده، NDP را جای ARP گذاشته و پیکربندی خودکار بدون سرور (SLAAC) را ممکن کرده است. آدرس در ۸ گروه ۱۶ بیتی هگزادسیمال نوشته می‌شود و با :: کوتاه می‌شود. 

بنویسید:  2001:0db8:0000:0000:0000:ff00:0042:8329
ساده‌شود: 2001:db8::ff00:42:8329

قوانین کوتاه‌سازی:
  ۱) صفرهای ابتدای هر گروه حذف می‌شوند:  0db8 → db8  و  0042 → 42
  ۲) یک‌بار مجاز است گروه‌های صفر متوالی با :: جمع شوند
  ۳) :: را جای یک گروه صفر تنها نگذارید؛ همان 0 بنویسید

انواع مهم:
  Global Unicast    2000::/3      آدرس عمومی قابل مسیریابی
  Unique Local      fc00::/7      مثل آدرس خصوصی IPv4 (پرکاربرد در سازمان)
  Link-Local        fe80::/10     فقط در همان لینک؛ خودکار روی هر اینترفیس
  Multicast         ff00::/8      جایگزین Broadcast
  Loopback          ::1/128       معادل 127.0.0.1

function Get-SubnetInfo {
    param([Parameter(Mandatory)][string]$CIDR)

    $ip, $prefix = $CIDR -split '/'
    $prefix = [int]$prefix

    # ماسک از روی تعداد بیت‌ها
    $bits = ('1' * $prefix).PadRight(32, '0')
    $maskOctets = 0..3 | ForEach-Object { [Convert]::ToInt32($bits.Substring($_ * 8, 8), 2) }
    $mask = $maskOctets -join '.'

    # تبدیل IP به عدد ۳۲ بیتی (Int64 برای پرهیز از سرریز علامت‌دار)
    $toNum = {
        param($s)
        $o = $s -split '\.' | ForEach-Object { [int64]$_ }
        ($o[0] -shl 24) + ($o[1] -shl 16) + ($o[2] -shl 8) + $o[3]
    }
    $toIp = {
        param([int64]$n)
        (($n -shr 24) -band 255), (($n -shr 16) -band 255),
        (($n -shr 8) -band 255), ($n -band 255) -join '.'
    }

    $ipNum   = & $toNum $ip
    $maskNum = & $toNum $mask
    $netNum  = $ipNum -band $maskNum
    $bcast   = $netNum + ([Math]::Pow(2, 32 - $prefix) - 1)

    [pscustomobject]@{
        Input         = $CIDR
        SubnetMask    = $mask
        Wildcard      = ($maskOctets | ForEach-Object { 255 - $_ }) -join '.'
        Network       = (& $toIp $netNum) + "/$prefix"
        FirstHost     = & $toIp ($netNum + 1)
        LastHost      = & $toIp ([int64]$bcast - 1)
        Broadcast     = & $toIp ([int64]$bcast)
        TotalIPv4     = [Math]::Pow(2, 32 - $prefix)
        UsableHosts   = [Math]::Pow(2, 32 - $prefix) - 2
    }
}

# ── ۶) اسکن زیرشبکه (Ping Sweep) — PowerShell 7+ ─────────────
function Invoke-PingSweep {
    param(
        [Parameter(Mandatory)][string]$Network,   # مثل: 192.168.1
        [int]$TimeoutSeconds = 1
    )
    Write-Host "Scanning $Network.0/24 ..."
    1..254 | ForEach-Object -Parallel {
        $ip = "$using:Network.$_"
        if (Test-Connection -ComputerName $ip -Count 1 -Quiet -TimeoutSeconds $using:TimeoutSeconds) {
            [pscustomobject]@{ IP = $ip; Status = 'UP' }
        }
    } -ThrottleLimit 64 | Sort-Object { [int]($_.IP -split '\.')[-1] }
}

function Get-NetworkReport {
    $rows = foreach ($adapter in Get-NetAdapter | Where-Object Status -eq 'Up') {
        $ipv4 = Get-NetIPAddress -InterfaceAlias $adapter.Name -AddressFamily IPv4 -ErrorAction SilentlyContinue
        $gw   = Get-NetRoute -InterfaceAlias $adapter.Name -DestinationPrefix '0.0.0.0/0' -ErrorAction SilentlyContinue
        $dns  = Get-DnsClientServerAddress -InterfaceAlias $adapter.Name -AddressFamily IPv4 -ErrorAction SilentlyContinue
        [pscustomobject]@{
            Interface  = $adapter.Name
            MAC        = $adapter.MacAddress
            IPv4       = $ipv4.IPAddress
            Prefix     = $ipv4.PrefixLength
            Gateway    = $gw.NextHop
            DNS        = ($dns.ServerAddresses -join ', ')
        }
    }
    $rows | Format-Table -AutoSize
    $csv = "NetworkReport_$(Get-Date -Format 'yyyyMMdd_HHmmss').csv"
    $rows | Export-Csv -Path $csv -NoTypeInformation -Encoding UTF8
    Write-Host "Saved: $csv" -ForegroundColor Green
}

Case Study ۱ — «همسایه‌ها جواب می‌دهند، اینترنت نه» سروری روی 10.10.0.15/24 می‌تواند 10.10.0.1 را پینگ کند اما 8.8.8.8 را نه. ip route get 8.8.8.8 نشان می‌دهد هیچ مسیر پیش‌فرضی وجود ندارد. با ip route add default via 10.10.0.1 مشکل حل می‌شود. پس از رفع، مسیر در netplan ماندگار می‌شود.
Case Study ۲ — «نیمی از کاربران به سرویس نمی‌رسند» یک سرویس روی 192.168.20.10/25 اجرا می‌شود. کاربران بازه‌ی .128 – .254 به آن نمی‌رسند، چون آن‌ها در زیرشبکه‌ی دیگرند و به‌جای رفتن از Router، ARP می‌زنند و پاسخی نمی‌گیرند. راه‌حل: یکسان‌کردن پیشوند روی همه‌ی کلاینت‌ها یا افزودن مسیر در Router.
Case Study ۳ — «پینگ OK، ولی دانلود بزرگ قطع می‌شود» دسترسی از طریق VPN برقرار است، ping با بسته‌ی کوچک موفق است ولی scp می‌شکند. تست با ping -M do -s 1472 شکست می‌خورد و با -s 1372 موفق می‌شود؛ یعنی MTU تونل کمتر از ۱۵۰۰ است. با تنظیم MSS Clamping روی Router (یا mtu روی اینترفیس تونل) مشکل حل می‌شود.

سوالات مهم (Q&A)

۱) چرا از هر زیرشبکه ۲ آدرس کم می‌کنیم؟ یک آدرس برای Network (همه‌ی بیت‌های میزبان صفر) و یکی برای Broadcast (همه‌ی بیت‌های میزبان یک) رزرو است. استثنا: /31 در لینک‌های Point-to-Point (RFC 3021) و /32 برای یک آدرس تک (Host Route).
۲) تفاوت Subnet Mask و Wildcard Mask چیست؟ ماسک بیت‌های شبکه را 1 و بیت‌های میزبان را 0 می‌گیرد؛ Wildcard دقیقاً برعکس است. مجموعشان همیشه 255.255.255.255 است. Wildcard در ACL و پروتکل‌های مسیریابی استفاده می‌شود.
۳) چطور سریع بفهمم دو IP در یک شبکه‌اند؟ هر دو را با ماسک AND کنید. اگر Network یکسان شد، هم‌شبکه‌اند؛ وگرنه ترافیک از Router می‌گذرد. با Python: ipaddress.ip_interface(a).network == ipaddress.ip_interface(b).network.
۴) تفاوت Subnetting و VLSM چیست؟ Subnetting همه‌ی زیرشبکه‌ها را هم‌اندازه می‌سازد؛ VLSM اجازه می‌دهد ماسک هر زیرشبکه متفاوت باشد و فضا بهینه مصرف شود. VLSM همیشه از بزرگ‌ترین نیاز شروع می‌شود.
۵) چرا ping 8.8.8.8 کار می‌کند اما ping google.com نه؟ یعنی IP و مسیریابی سالم است و فقط نام‌گذاری مشکل دارد: resolv.conf یا /etc/hosts یا سرور DNS. با dig @1.1.1.1 google.com تفکیک کنید.
۶) آدرس 169.254.x.x چه معنایی دارد؟ Link-Local یا APIPA است؛ یعنی کلاینت نتوانسته از DHCP آدرس بگیرد و خودش یکی ساخته. تقریباً همیشه نشانه‌ی مشکل در DHCP، کابل یا VLAN است — نه یک آدرس سالم.
۷) NAT چه‌کار می‌کند و چرا لازم است؟ آدرس‌های خصوصی در اینترنت مسیریابی نمی‌شوند. NAT در لبه، آدرس داخلی را به یک آدرس عمومی ترجمه می‌کند و به‌این‌ترتیب هزاران دستگاه با یک آدرس عمومی به بیرون می‌روند.
۸) چرا IPv6 در LAN همیشه /64 است؟ چون SLAAC و Autoconfiguration بر پایه‌ی ۶۴ بیت اینترفیس طراحی شده‌اند. شکستن /64 روی LAN باعث می‌شود بخش زیادی از دستگاه‌ها نتوانند خودکار آدرس بگیرند.
۹) Route Summarization چگونه محاسبه می‌شود؟ شبکه‌های پیوسته و هم‌تراز را به باینری ببرید و طولانی‌ترین پیشوند مشترک را پیدا کنید. پیشوند نتیجه، همان طول مشترک است: چهار شبکه‌ی /24 پشت‌سرهم → /22.
۱۰) چرا از ifconfig به ip مهاجرت کنیم؟ ip سریع‌تر، اتمیک‌تر، از IPv6 بومی پشتیبانی می‌کند و کارهایی مثل ip route get و ip -br را ممکن می‌کند که در مجموعه‌ی قدیمی معادل ساده‌ای ندارند.
