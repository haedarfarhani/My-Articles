بخش ۱مقدمه

Docker برنامه و همه‌ی وابستگی‌هایش را در یک Image بسته‌بندی می‌کند و آن را به‌عنوان یک Container سبک اجرا می‌کند. این کار تفاوت‌های محیط توسعه و Production را حذف می‌کند و استقرار را قابل‌تکرار می‌سازد.

در این مقاله مفهوم Image و Container، لایه‌ها، Dockerfile حرفه‌ای، Volume و Network و Compose.
Prerequisites استقرار Production و NGINX.

بخش ۴Dockerfile و Best Practice

# Multi-stage build — تصویر نهایی کوچک و امن
FROM maven:3.9-eclipse-temurin-21 AS build
WORKDIR /build
COPY pom.xml .
RUN mvn -q dependency:go-offline
COPY src ./src
RUN mvn -q -DskipTests package

FROM eclipse-temurin:21-jre-alpine
WORKDIR /app
COPY --from=build /build/target/app.jar app.jar

# کاربر غیر root
RUN addgroup -S app && adduser -S app -G app
USER app

ENV JAVA_OPTS="-Xmx384m"
EXPOSE 8080
HEALTHCHECK --interval=30s --timeout=3s \
  CMD wget -qO- http://127.0.0.1:8080/health || exit 1
ENTRYPOINT ["sh","-c","java $JAVA_OPTS -jar app.jar"]
Expected Behavior تصویر نهایی فقط JRE و فایل JAR را دارد، با کاربر غیر root اجرا می‌شود و Docker می‌تواند سلامت آن را خودکار بسنجد.
Best Practiceدلیل

.dockerignoreکاهش Context و جلوگیری از کپی Secrets
Pin کردن نسخهبازتولیدپذیری
کاربر غیر rootکاهش سطح حمله
HEALTHCHECKRestart خودکار در صورت خرابی

بخش ۵Volume، Network و Compose

# docker-compose.yml
services:
  nginx:
    image: nginx:1.27-alpine
    ports: ["80:80", "443:443"]
    volumes:
      - ./nginx.conf:/etc/nginx/nginx.conf:ro
    depends_on: [app]

  app:
    image: registry.example.com/app:1.4.2
    environment:
      - DB_HOST=db
      - DB_USER=${DB_USER}
      - DB_PASSWORD=${DB_PASSWORD}
    deploy:
      replicas: 3
    depends_on: [db, redis]

  db:
    image: postgres:16
    volumes: ["pgdata:/var/lib/postgresql/data"]
    environment: { POSTGRES_PASSWORD: ${DB_PASSWORD} }

  redis:
    image: redis:7-alpine

volumes: { pgdata: {} }
networks: { default: { driver: bridge } }
Expected Behavior Compose یک شبکه‌ی خصوصی می‌سازد که سرویس‌ها با نام (مثلاً db) یکدیگر را می‌بینند و داده‌ی Postgres در Volume پایدار می‌ماند.
Secrets هرگز رمز را داخل Image یا Compose نسپارید؛ از Environment و Secret Manager استفاده کنید و .env را در .gitignore بگذارید.

بخش ۶Deployment و جمع‌بندی

docker build -t registry.example.com/app:1.4.2 .
docker push registry.example.com/app:1.4.2

# روی سرور
docker pull registry.example.com/app:1.4.2
docker compose up -d --no-deps --build app
docker compose ps
docker compose logs -f app
به‌روزرسانی امن با --no-deps فقط سرویس برنامه به‌روز می‌شود و سرویس‌های وابسته دست‌نخورده می‌مانند؛ برای Zero-Downtime، چند Replica و Reverse Proxy لازم است.
AdvantagesDisadvantages
استقرار یکسان و قابل‌تکرارنیاز به دانش شبکه و Storage
سبک و سریعمدیریت Volume و بکاپ جداگانه
پایه‌ی Kubernetesبرای پروژه‌های کوچک، گاهی پیچیده است
When to Useاکثر سرویس‌های مدرن؛ به‌ویژه وقتی Microservice یا چند محیط متفاوت دارید.

Docker مرز بین توسعه و Production را محو می‌کند. با Image تمیز، Volume پایدار و Compose ساده، می‌توانید استقرار قابل‌اعتماد داشته باشید و پایه‌ی مسیر Kubernetes را هم آماده کنید.
