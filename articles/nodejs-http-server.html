Node.js HTTP Server؛ از http خالص تا PM2 در Production

Node.js می‌تواند خودش یک Application Server کامل باشد. مدل Event Loop، ماژول http، فریمورک‌هایی مثل Express و Fastify، و ابزارهایی مثل Cluster و PM2 تعیین می‌کنند این سرور در Production چه رفتار و چه ظرفیتی داشته باشد. در این مقاله از پایه تا استقرار واقعی را مرور می‌کنیم.

بخش ۱مقدمه

Node.js یک Runtime برای اجرای JavaScript در سمت سرور است. برخلاف Java یا .NET که معمولاً یک Application Server جداگانه لازم دارند، در Node.js خودِ برنامه سرور HTTP را می‌سازد و بالا می‌آورد. همین ویژگی هم سادگی می‌آورد و هم مسئولیت: باید بدانید Event Loop چگونه کار می‌کند، داخل کانتینر چند Process لازم است، و چرا معمولاً NGINX را جلوی Node.js می‌گذاریم.

در این مقاله مدل اجرای Node.js، ساخت سرور با http و Express/Fastify، Clustering با pm2 و cluster، و تنظیمات Production.
Prerequisites Web Server vs Application Server و NGINX + Node.js.

بخش ۲Event Loop و مدل اجرا

Node.js بر پایه‌ی Single-threaded Event Loop است. همه‌ی درخواست‌های I/O (شبکه، فایل، دیتابیس) به‌صورت غیرهمگام (Asynchronous) و توسط سیستم‌عامل مدیریت می‌شوند و Callback آن‌ها روی همان یک Thread اجرا می‌شود. یعنی Node برای بارهای I/O-bound بسیار سبک و کارآمد است.

نوع باررفتار Node.js
I/O-bound (شبکه، دیتابیس)عالی — هزاران Connection همزمان با یک Thread
CPU-bound (پردازش سنگین، رمزنگاری)ضعیف — Event Loop را قفل می‌کند
Golden Rule هرچیز CPU-bound (Hash سنگین، پردازش تصویر، JSON بزرگ) باید به Worker Threads، worker_threads یا یک سرویس جدا منتقل شود؛ وگرنه کل سرور برای بقیه‌ی درخواست‌ها کند می‌شود.

بخش ۳معماری Node.js در Production

بخش ۴از http خالص تا Express

// 1) سرور خالص با ماژول http
import http from "node:http";

const server = http.createServer((req, res) => {
  if (req.url === "/health") {
    res.writeHead(200, { "Content-Type": "application/json" });
    res.end(JSON.stringify({ status: "ok" }));
    return;
  }
  res.writeHead(404);
  res.end("Not Found");
});

server.keepAliveTimeout = 65_000;   // بیشتر از Keep-Alive پروکسی
server.headersTimeout   = 66_000;
server.listen(3000, "0.0.0.0");
// 2) همان سرویس با Express
import express from "express";

const app = express();
app.set("trust proxy", 1);          // احترام به X-Forwarded-*
app.use(express.json({ limit: "1mb" }));

app.get("/health", (_req, res) => res.json({ status: "ok" }));
app.get("/users/:id", async (req, res, next) => {
  try {
    res.json(await db.findUser(req.params.id));
  } catch (err) { next(err); }
});

app.listen(3000, "0.0.0.0");
Expected Behavior هر دو مثال یک Endpoint سلامت (/health) دارند که برای Load Balancer و Kubernetes Probe حیاتی است، و روی 0.0.0.0 Bind می‌شوند تا از بیرون کانتینر قابل دسترس باشند.
Express یا Fastify؟ Express بالغ و پرکاربرد است؛ Fastify سبک‌تر، سریع‌تر و دارای Schema Validation داخلی است. برای پروژه‌های جدید با تمرکز بر Throughput، Fastify انتخاب خوبی است.

بخش ۵Clustering و PM2

یک Process Node.js فقط از یک هسته‌ی CPU استفاده می‌کند. برای بهره‌گیری از چند هسته، از ماژول cluster یا مدیر فرآیندی مثل PM2 استفاده می‌کنیم که چند Worker می‌سازد و ترافیک را بین آن‌ها پخش می‌کند. 

// cluster: یک Master و N Worker
import cluster from "node:cluster";
import { cpus } from "node:os";

if (cluster.isPrimary) {
  for (let i = 0; i < cpus().length; i++) cluster.fork();
  cluster.on("exit", (w) => setTimeout(() => cluster.fork(), 1000));
} else {
  startServer();     // همان سرور http/Express
}
# PM2 — مدیریت و راه‌اندازی مجدد خودکار
pm2 start app.js -i max --name api \
    --max-memory-restart 512M

pm2 save        # ثبت برای اجرا پس از ری‌استارت
pm2 startup     # ساخت سرویس systemd
pm2 logs        # مشاهده‌ی لاگ‌ها
pm2 monit       # پایش زنده
State را به حافظه نسپارید با چند Worker، هر Process حافظه‌ی جدا دارد. Session، Rate Limit و Queue را در Redis مشترک نگه دارید، نه در متغیر داخل Process.

بخش ۶Performance و نکات Production

موضوعتصمیم Production
تعداد Workerبرابر تعداد هسته‌های CPU (یا max در PM2)
Keep-Aliveروشن، با Timeout کمی بیشتر از پروکسی
Heap--max-old-space-size متناسب با RAM کانتینر
Restart خودکار--max-memory-restart و Health Check
SecretsEnvironment Variable، نه داخل کد
Static Filesسرو توسط NGINX، نه Node
Production Note اگر حافظه‌ی کانتینر ۵۱۲MB است، --max-old-space-size=380 بگذارید تا Garbage Collector قبل از OOM-Kill شدن کانتینر فضای لازم را داشته باشد.
