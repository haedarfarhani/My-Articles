Apache TomEE؛ Tomcat با قدرت کامل Jakarta EE

TomEE همان Tomcat است که با پشته‌ی Jakarta EE گسترش یافته: CDI، EJB، JPA، JAX-RS، JMS، JNDI و Transaction. این مقاله نشان می‌دهد چه زمانی TomEE انتخاب درستی است و چه زمانی Tomcat یا WildFly مناسب‌تر است.

بخش ۱مقدمه

Tomcat یک Servlet Container عالی است، اما اگر به قابلیت‌های Enterprise نیاز دارید — Transaction مدیریت‌شده، EJB، JMS، CDI و JPA آماده — یا باید کتابخانه‌ها را دستی اضافه کنید یا از یک Application Server کامل استفاده کنید. TomEE دقیقاً همین میانه را پر می‌کند: هسته‌ی آشنای Tomcat به‌همراه پروفایل‌های Jakarta EE.

در این مقاله تفاوت Tomcat و TomEE، اجزای Jakarta EE، پیکربندی Transaction و DataSource، و مقایسه‌ی TomEE با WildFly.
Prerequisites Apache Tomcat.

بخش ۲TomEE چیست؟

تعریف Apache TomEE نسخه‌ای از Tomcat است که با پشته‌ی Jakarta EE (Web Profile یا Full Profile) غنی شده و امکاناتی مثل CDI، EJB Lite، JPA، JAX-RS، JMS و Transaction مدیریت‌شده را در همان فرآیند در اختیار برنامه می‌گذارد.
پروفایلمحتوای اصلی
tomee-webprofileServlet، JSP، CDI، JPA، EJB Lite، JAX-RS، JMS سبک
tomee-plusWebProfile + JAX-WS و قابلیت‌های بیشتر
tomee-plumeکامل‌تر با JMS و ابزارهای اضافه

بخش ۴پیکربندی و مثال

<!-- conf/tomee.xml : DataSource با JNDI -->
<Resource id="appdb" type="DataSource">
  JdbcDriver   org.postgresql.Driver
  JdbcUrl      jdbc:postgresql://db.internal:5432/app
  UserName     ${DB_USER}
  Password     ${DB_PASSWORD}
  JtaManaged   true
</Resource>
@Path("/orders")
@RequestScoped
public class OrderResource {

    @Inject
    OrderService service;          // CDI

    @GET
    @Path("/{id}")
    public OrderDto get(@PathParam("id") long id) {
        return service.find(id);
    }
}

@Stateless                          // EJB
public class OrderService {
    @PersistenceContext EntityManager em;   // JPA + Transaction مدیریت‌شده

    @Transactional
    public OrderDto find(long id) {
        return OrderDto.from(em.find(Order.class, id));
    }
}
Expected Behavior یک درخواست GET /orders/42 از NGINX به TomEE می‌رسد، CDI وابستگی را تزریق می‌کند، EJB تراکنش را باز می‌کند و JPA داده را از دیتابیس می‌خواند.
Annotation-driven بخش بزرگی از TomEE مبتنی بر Annotation است؛ همین موضوع پیکربندی XML را کم و کد را خواناتر می‌کند.

بخش ۵Production و Security

موضوعتصمیم Production
JVM Heap-Xms=-Xmx و G1GC
Transaction Logروی دیسک پایدار، نه حافظه‌ی موقت
Connection Poolهماهنگ با maxThreads و ظرفیت دیتابیس
Secretsاز Environment Variable یا JNDI سطح سرور، نه داخل WAR
ورودیفقط از شبکه‌ی خصوصی؛ NGINX تنها نقطه‌ی عمومی
# اجرا با systemd و تنظیمات Production
JAVA_OPTS="-Xms512m -Xmx1024m -XX:+UseG1GC" \
  $TOMEE_HOME/bin/catalina.sh run

# Docker
docker run -d --name tomee -p 127.0.0.1:8080:8080 \
  tomee:webprofile10-jdk21
Production Note برای Jakarta EE 10 از TomEE 9/10 و فضای‌نام jakarta.* استفاده کنید. برنامه‌های قدیمی‌تر با javax.* نیازمند نسخه‌ی سازگار TomEE هستند.

When to Useبرنامه‌های Jakarta EE که به Transaction، EJB و JMS نیاز دارند و می‌خواهند از سبکی Tomcat سود ببرند.
When NOT to Useاگر با Spring Boot کار می‌کنید، سرور تعبیه‌شده کافی است. برای Clustering و Jakarta EE کامل، WildFly گزینه‌ی دقیق‌تری است.

TomEE پل بین سبکی Tomcat و کامل‌بودن Application Serverهای Enterprise است. اگر مرزهایش را بفهمید، انتخاب درستی برای سرویس‌های Java سازمانی خواهد بود.
